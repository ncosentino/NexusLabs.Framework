# NLS0001: Use UUIDv7 Create() instead of the generated New() method

UUIDv7-enabled identifiers must use their generated `Create()` method. The
built-in GUID template's parameterless `New()` method calls `Guid.NewGuid()` and
therefore produces UUIDv4.

## Why this rule exists

The additive UUIDv7 template intentionally retains the existing GUID-backed
identifier implementation. That also retains its `New()` method, whose behavior
cannot be replaced by another additive template. Calling it silently bypasses
the identifier's configured UUIDv7 creation policy.

## Bad

```csharp
OrderId orderId = OrderId.New();
Func<OrderId> factory = OrderId.New;
```

## Good

```csharp
OrderId orderId = OrderId.Create();
Func<OrderId> factory = OrderId.Create;
```

Use `OrderId.Create(timeProvider)` when tests or infrastructure need to control
the UUIDv7 timestamp.

## Suppression

Suppressing this error means deliberately opting the UUIDv7-enabled identifier
back into UUIDv4 generation. Prefer a separately modeled identifier when UUIDv4
is genuinely required.

Construction from an externally sourced GUID remains allowed for persistence
and deserialization; NLS0002 only rejects the direct `Guid.NewGuid()` creation
path.
