# NLF0003 — Check TriedEx.Success is false before accessing Error

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

`TriedEx<T>.Error` and `TriedNullEx<T>.Error` are only meaningful when
`Success` is `false`. Reading `Error` when `Success` is `true` returns
`null` and indicates a logic bug in the caller. Guard the access first.

## Bad

```csharp
TriedEx<string> result = await TryFetchAsync();
_logger.LogError(result.Error, "fetch failed"); // null when Success == true
```

## Good — early return

```csharp
TriedEx<string> result = await TryFetchAsync();
if (result.Success)
{
    return result.Value;
}

_logger.LogError(result.Error, "fetch failed");
```

## Good — Match for both branches in one expression

```csharp
TriedEx<string> result = await TryFetchAsync();
result.Match(
    onSuccess: value => _logger.LogInformation("got {Value}", value),
    onError:   ex    => _logger.LogError(ex, "fetch failed"));
```

## When suppression is legitimate

Almost never. Promote to error in projects that consume the Try pattern
heavily:

```ini
# .editorconfig
[*.cs]
dotnet_diagnostic.NLF0003.severity = error
```
