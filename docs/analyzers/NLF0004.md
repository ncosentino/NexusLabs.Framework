# NLF0004 — Remove redundant Error null check on Success-false branch

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

`TriedEx<T>` and `TriedNullEx<T>` guarantee `Error` is non-null whenever
`Success` is false. Once the Success-false branch is established, a null
check on `Error` is dead code and obscures intent.

## Bad

```csharp
if (!result.Success)
{
    if (result.Error == null)            // dead branch
    {
        throw new InvalidOperationException("unreachable");
    }

    _logger.LogError(result.Error, "fetch failed");
}
```

```csharp
if (result.Success)
{
    return result.Value;
}

// else-of-Success-check — Error is guaranteed non-null here too
if (result.Error is not null)            // redundant
{
    _logger.LogError(result.Error, "fetch failed");
}
```

## Good

```csharp
if (!result.Success)
{
    _logger.LogError(result.Error, "fetch failed");
}
```

## When suppression is legitimate

Almost never. The redundancy is a code-smell; remove it instead.
