# NLF0001 — Replace Console/Debug.Write with ILogger in library code

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

Library code that needs to emit observable output should route through
`ILogger` (or an equivalent injectable abstraction) rather than calling
`System.Console.Write*` or `System.Diagnostics.Debug.Write*` directly.
Direct console/debug output ignores the host's logging configuration —
sinks, filtering, structured logging, and correlation context are all
bypassed.

## Bad

```csharp
public sealed class Worker
{
    public void Run()
    {
        Console.WriteLine("starting...");
        Debug.WriteLine("debug detail");
    }
}
```

## Good

```csharp
public sealed class Worker
{
    private readonly ILogger<Worker> _logger;

    public Worker(ILogger<Worker> logger) => _logger = logger;

    public void Run()
    {
        _logger.LogInformation("starting...");
        _logger.LogDebug("debug detail");
    }
}
```

Or, when injecting a logger is impractical, accept a callback parameter
so the caller controls output:

```csharp
public void Run(Action<string>? log = null) => log?.Invoke("starting...");
```

## When suppression is legitimate

Entry-point executables (CLI tools, samples, hosting startup) may
legitimately write to the console. Suppress for those projects:

```ini
# .editorconfig
[*.cs]
dotnet_diagnostic.NLF0001.severity = none
```
