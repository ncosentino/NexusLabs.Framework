# NLF0006 — Replace whole-body try-catch with Try.Async / Try.GetAsync

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

An async method whose body is exactly one `try { ... } catch { ... }` is
the canonical case the `NexusLabs.Framework.Try` helpers exist to
abstract. Replacing the manual try-catch with the appropriate Try variant
centralizes the catch policy and pairs cleanly with NLF0002..NLF0005 at
the call site.

## Bad

```csharp
public async Task<TriedEx<User>> GetUserAsync(int id)
{
    try
    {
        var user = await _repo.GetByIdAsync(id);
        return user;
    }
    catch (Exception ex)
    {
        return ex;
    }
}
```

## Good — Try.GetAsync (returns TriedEx<T>)

```csharp
public Task<TriedEx<User>> GetUserAsync(int id) =>
    Try.GetAsync(_logger, async () => await _repo.GetByIdAsync(id));
```

## Good — Try.GetOrNullAsync (returns TriedNullEx<T?>)

```csharp
public Task<TriedNullEx<User?>> TryGetUserAsync(int id) =>
    Try.GetOrNullAsync(_logger, async () => await _repo.GetByIdAsync(id));
```

## Good — Try.Async (returns Task&lt;Exception?&gt; for fire-and-fail)

```csharp
public Task<Exception?> InitializeAsync() =>
    Try.Async(_logger, async () => await _bootstrapper.RunAsync());
```

## When suppression is legitimate

If the catch performs side effects beyond returning an exception (cleanup,
re-throw of a different type, retry), the manual try-catch may be the
right shape. Refactor the side effect into a separate operation if
possible.
