# NLF0005 — Preserve original Error when returning an exception from a Success-false branch

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

When the Success-false branch of a `TriedEx<T>` / `TriedNullEx<T>` returns
an `Exception`, the original `Error` must be carried forward. Returning a
fresh exception that ignores `result.Error` silently drops the underlying
failure and breaks observability (stack trace, inner cause, telemetry
correlation).

## Bad

```csharp
if (!result.Success)
{
    return new InvalidOperationException("could not fetch user");
    // original result.Error is dropped
}
```

## Good — return Error directly

```csharp
if (!result.Success)
{
    return result.Error;
}
```

## Good — wrap with InnerException

```csharp
if (!result.Success)
{
    return new InvalidOperationException("could not fetch user", result.Error);
}
```

## Good — aggregate

```csharp
if (!result.Success)
{
    return new AggregateException(result.Error, otherFailure);
}
```

## When suppression is legitimate

Almost never. If the original error is genuinely unactionable (e.g. the
inner exception type leaks an implementation detail you cannot expose),
log it at the same site before discarding:

```csharp
if (!result.Success)
{
    _logger.LogError(result.Error, "internal fetch failure (discarded)");
    return new UserVisibleException("could not load");
}
```
