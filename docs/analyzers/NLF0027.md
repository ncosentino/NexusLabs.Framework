# NLF0027 — Use `System.TimeProvider` instead of a custom time abstraction

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

An interface that reimplements `System.TimeProvider`.

`TimeProvider` has been in the BCL since .NET 8 and is what
`Task.Delay`, `CancellationTokenSource`, `PeriodicTimer`, and
`Microsoft.Extensions.TimeProvider.Testing` are all built around. A
hand-rolled equivalent gains none of that: the delay it wraps
cannot be advanced by a fake clock, every consumer has to be
migrated later, and the migration itself tends to introduce
[NLF0025](NLF0025.md) regressions when the custom `DelayAsync` has
no direct counterpart.

## Bad — clock plus its own delay primitive

```csharp
// ❌ NLF0027 — 1 clock member and 1 delay member.
public interface ITimeProvider
{
    DateTimeOffset GetUtcNow();

    Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken);
}
```

This pairing is the most common hand-rolled shape and is reported
rather than exempted. The delay member is precisely what makes the
abstraction expensive to remove: it has no one-to-one BCL
replacement, so every call site has to be rewritten to
`Task.Delay(delay, timeProvider, cancellationToken)`.

## Bad — clock only

```csharp
// ❌ NLF0027 — 1 clock member.
public interface IClock
{
    DateTime UtcNow { get; }
}
```

## Good — depend on the BCL type

```csharp
public sealed class OrderService(TimeProvider timeProvider)
{
    public async Task PlaceAsync(Order order, CancellationToken cancellationToken)
    {
        order.PlacedAt = timeProvider.GetUtcNow();
        await Task.Delay(order.SettleDelay, timeProvider, cancellationToken);
    }
}
```

Tests substitute `FakeTimeProvider` and advance it. No abstraction
of your own is required.

## What the analyzer actually checks

The type must be an **interface**, must have at least one member,
and **every** member must be time related, with at least one clock
member.

A **clock member** is a property or ordinary method named `Now`,
`UtcNow`, `GetNow`, `GetUtcNow`, `GetLocalNow`, `CurrentTime`, or
`GetTimestamp`, returning `DateTime`, `DateTimeOffset`, or `long`.

A **delay member** is an ordinary method named `Delay`,
`DelayAsync`, `Sleep`, `SleepAsync`, `WaitAsync`, or `CreateTimer`
that takes a `System.TimeSpan`.

Property accessors are counted through their property symbol, not
separately, so a clock-only interface is not mistaken for one with
unrelated members.

## When the analyzer stays silent

- The type is a class or struct, not an interface. Concrete clocks
  are frequently legitimate — including subclasses of
  `TimeProvider` itself.
- The interface has no clock member at all. An interface that only
  exposes a delay is a throttle or scheduler, not a clock.
- Not every member is time related. A broader abstraction that
  merely happens to expose a timestamp is not a reimplementation of
  `TimeProvider`:

```csharp
// ✅ no diagnostic — WriteAsync makes this an audit sink, not a clock.
public interface IAuditSink
{
    DateTimeOffset GetUtcNow();

    Task WriteAsync(string message);
}
```

## When suppression is the correct choice

An abstraction that genuinely cannot be expressed as a
`TimeProvider`, or a deprecated type kept for one more major
version so consumers can migrate:

```csharp
[Obsolete("Use System.TimeProvider directly. Removed in the next major version.")]
#pragma warning disable NLF0027 // This is the shape the rule exists to prevent; kept only for migration.
public interface ITimeProvider
{
    DateTimeOffset GetUtcNow();

    Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken);
}
#pragma warning restore NLF0027
```

That is exactly how `NexusLabs.Framework`'s own obsolete
`ITimeProvider` is handled.

Or opt out per-project with
`dotnet_diagnostic.NLF0027.severity = none`.
