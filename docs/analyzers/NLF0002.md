# NLF0002 — Check TriedEx.Success before accessing Value

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

`TriedEx<T>.Value` and `TriedNullEx<T>.Value` are only valid when `Success`
is `true`. Reading `Value` when `Success` is `false` throws
`InvalidOperationException` at runtime. Guard the access first.

## Bad

```csharp
TriedEx<string> result = await TryFetchAsync();
Console.WriteLine(result.Value); // throws if Success == false
```

## Good — early return

```csharp
TriedEx<string> result = await TryFetchAsync();
if (!result.Success)
{
    return result.Error;
}

Console.WriteLine(result.Value);
```

## Good — Match for both branches in one expression

```csharp
TriedEx<string> result = await TryFetchAsync();
string display = result.Match(
    onSuccess: value => value,
    onError:   ex    => $"<error: {ex.Message}>");
```

## Good — guarded short-circuit

```csharp
if (result.Success && result.Value.StartsWith("foo"))
{
    // ...
}
```

## When suppression is legitimate

Almost never. Promote to error in projects that consume the Try pattern
heavily:

```ini
# .editorconfig
[*.cs]
dotnet_diagnostic.NLF0002.severity = error
```
