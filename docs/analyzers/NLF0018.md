# NLF0018 — `CancellationToken` parameters must not have a default value

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

Every method, constructor, local function, or delegate signature
that has a `System.Threading.CancellationToken` parameter must
declare that parameter as **required** — no `= default`, no
`= default(CancellationToken)`, no `= CancellationToken.None`, no
`= new CancellationToken()`.

Optional `CancellationToken` parameters let callers silently drop
the token. The downstream I/O then ignores cancellation and never
stops cleanly on shutdown, request-abort, or timeout: requests
that should cancel leak into background work, retry loops cannot
be stopped, and tests that forget to thread the token hang
indefinitely on assertion timeouts. The cost of the rule is one
explicit `CancellationToken.None` at the rare call site that
genuinely has no token; the benefit is a build-time guarantee
that every other call site has consciously chosen which token
to pass.

NLF0018 has **no built-in scope filter** — it applies to every
parameter on every member of every type in the project, including
interfaces, abstract methods, constructors, static methods, local
functions, and delegate signatures. The only escape hatch is
`#pragma warning disable NLF0018` at the call site (for
intentional ergonomic-default public APIs or
`[EnumeratorCancellation]` IAsyncEnumerable iterators) or
`dotnet_diagnostic.NLF0018.severity = none` in `.editorconfig`
for an entire project.

## Bad — optional CancellationToken

```csharp
public sealed class UserService
{
    // ❌ NLF0018 — callers can omit the token; cancellation silently lost.
    public Task<User?> GetByIdAsync(UserId id, CancellationToken cancellationToken = default)
        => /* ... */;

    // ❌ NLF0018 — same as above with the explicit type spelled out.
    public Task DoAsync(CancellationToken cancellationToken = default(CancellationToken))
        => /* ... */;

    // ❌ NLF0018 — CancellationToken.None as the default has the same problem.
    public Task DeleteAsync(CancellationToken cancellationToken = default)
        => /* ... */;
}

public interface IUserRepository
{
    // ❌ NLF0018 — interface declarations are also held to the rule.
    Task<User?> GetByIdAsync(UserId id, CancellationToken cancellationToken = default);
}
```

## Good — required CancellationToken

```csharp
public sealed class UserService
{
    public Task<User?> GetByIdAsync(UserId id, CancellationToken cancellationToken)
        => /* ... */;

    public Task DoAsync(CancellationToken cancellationToken) => /* ... */;
}

public interface IUserRepository
{
    Task<User?> GetByIdAsync(UserId id, CancellationToken cancellationToken);
}
```

## Good — call sites that truly have no token pass `CancellationToken.None` explicitly

```csharp
// In a fire-and-forget startup task with no caller-supplied token:
await _userService
    .DoAsync(CancellationToken.None)
    .ConfigureAwait(false);

// In a synchronous bootstrap path that cannot await:
_userService
    .DoAsync(CancellationToken.None)
    .GetAwaiter()
    .GetResult();
```

The discipline is the point: `CancellationToken.None` at the call
site is a visible, grep-able marker that someone consciously
decided not to thread a token here. An omitted argument leaves
no such trace.

## When the analyzer stays silent

- The parameter is not `CancellationToken` (different type, even
  if named `cancellationToken`).
- The parameter has no `EqualsValueClause` — i.e. it is required.
- The parameter is `params CancellationToken[]` — not a single
  optional `CancellationToken`. (Atypical; rule does not trigger.)

The rule does NOT skip:

- Public APIs of a library
- Interface declarations
- Abstract methods
- Constructors
- Static methods
- Extension methods
- Local functions
- Delegate signatures
- `[EnumeratorCancellation]`-decorated `IAsyncEnumerable` iterators

Each of those is held to the same rule. Suppress them at the
call site if the default is genuinely intentional (see below).

## When suppression is the correct choice

There are two recurring legitimate patterns where the default
value is genuinely intentional and `#pragma warning disable NLF0018`
at the declaration is the right answer:

### 1. Public-API ergonomic-default companion overload

A library that ships both `Method(CancellationToken)` and
`Method(TimeSpan, CancellationToken)` may also want
`Method(CancellationToken = default)` so callers in synchronous
top-level contexts (e.g. console-app `Main`) can call it without
threading anything. Mark the default-bearing overload with the
suppression and an inline comment:

```csharp
public static class SemaphoreSlimExtensions
{
    extension(SemaphoreSlim semaphore)
    {
        // Ergonomic default for top-level callers that have no token
        // to thread; companion overloads exist that take timeout +
        // mandatory CancellationToken for caller-controlled cancellation.
#pragma warning disable NLF0018
        public async Task<AsyncSemaphoreLease> AcquireAsync(
            CancellationToken cancellationToken = default)
#pragma warning restore NLF0018
        {
            await semaphore.WaitAsync(cancellationToken).ConfigureAwait(false);
            return new AsyncSemaphoreLease(semaphore);
        }
    }
}
```

### 2. `[EnumeratorCancellation]` `IAsyncEnumerable` iterators

The BCL convention for cancellable `IAsyncEnumerable<T>` iterators
is `[EnumeratorCancellation] CancellationToken cancellationToken = default`.
The default lets `await foreach (var x in source.Iter())` work
without explicit-token plumbing — `WithCancellation` then flows
the token via the attribute. Removing the default breaks the
convention. Suppress with rationale:

```csharp
public static class TaskExtensions
{
    // BCL [EnumeratorCancellation] pattern — the default is required so
    // `await foreach (var x in source.WhenEach())` works and
    // `WithCancellation(token)` can flow a token via the attribute.
#pragma warning disable NLF0018
    public static async IAsyncEnumerable<(int Index, T Value)> WhenEachWithIndex<T>(
        this IEnumerable<Task<T>> tasks,
        [EnumeratorCancellation] CancellationToken cancellationToken = default)
#pragma warning restore NLF0018
    {
        /* ... */
    }
}
```

For an entire library project where every public method has an
ergonomic-default `CancellationToken`, opt out via
`dotnet_diagnostic.NLF0018.severity = none` in `.editorconfig`.

## What the analyzer actually checks

The match is mechanical: any `ParameterSyntax` whose
`EqualsValueClause` is non-null AND whose declared type resolves
to `System.Threading.CancellationToken`. The default expression
text is included in the diagnostic message so the consumer can
see at a glance which default form they used (`default`,
`default(CancellationToken)`, `CancellationToken.None`,
`new CancellationToken()`).

The rule does not inspect the *value* of the default — it
inspects the OPTIONAL-ness of the parameter. A non-default
expression on a `CancellationToken` parameter (e.g.
`= someStaticReadonlyToken`) is unusual but also flagged because
the underlying contract is the same: callers can omit the
argument.

## Related rules

- **CA2016** (Microsoft NetAnalyzers) — "Forward the
  CancellationToken parameter to methods that take one" — flags
  call sites that drop the token at the invocation boundary.
  NLF0018 attacks the same problem from the declaration side:
  if every declaration requires the token, the call site cannot
  drop it accidentally. The two rules compose — together they
  push the token end-to-end through the call graph.
