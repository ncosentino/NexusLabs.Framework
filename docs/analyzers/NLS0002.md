# NLS0002: Use UUIDv7 Create() instead of constructing from Guid.NewGuid()

Passing `Guid.NewGuid()` directly to a UUIDv7-enabled identifier constructor
creates UUIDv4 and bypasses the generated UUIDv7 creation API.

## Why this rule exists

The GUID constructor must remain available for parsing, persistence,
deserialization, and rehydration. Consequently, the type cannot prove that every
constructed value is UUIDv7. This rule targets the unambiguous UUIDv4 generation
case without rejecting legitimate external GUID provenance.

## Bad

```csharp
OrderId orderId = new OrderId(Guid.NewGuid());
OrderId targetTyped = new(Guid.NewGuid());
```

## Good

```csharp
OrderId orderId = OrderId.Create();

Guid storedValue = await repository.GetOrderIdAsync(cancellationToken);
OrderId rehydrated = new OrderId(storedValue);
```

The analyzer intentionally does not trace arbitrary variables back through
control flow. A GUID received from a parameter, database, message, or
deserializer remains valid input to the constructor.

## Suppression

Suppress only when a UUIDv4 value is deliberately being placed in a type whose
normal creation policy is UUIDv7. Prefer a separately modeled identifier if
mixed generation policies are expected.
