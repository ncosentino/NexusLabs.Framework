# NLF0009 — Wrap async method returning TriedEx&lt;T&gt; with Try.GetAsync

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

An async method whose return type is `Task<TriedEx<T>>` or
`Task<TriedNullEx<T>>` is promising the caller that it will swallow
exceptions into the `Error` slot. Without `Try.GetAsync` /
`Try.GetOrNullAsync` wrappers, an uncaught exception will fault the
`Task` instead of populating `Error`, breaking the contract.

## Bad

```csharp
public async Task<TriedEx<User>> GetUserAsync(int id)
{
    return await _repo.GetByIdAsync(id);
    // throws into Task, never reaches TriedEx
}
```

## Good — wrap with Try.GetAsync

```csharp
public Task<TriedEx<User>> GetUserAsync(int id) =>
    Try.GetAsync(_logger, async () => await _repo.GetByIdAsync(id));
```

## Good — direct pass-through (inner method owns the catch)

```csharp
public Task<TriedEx<User>> GetUserAsync(int id) =>
    _inner.GetUserAsync(id);  // _inner.GetUserAsync already wraps with Try.GetAsync
```

```csharp
public async Task<TriedEx<User>> GetUserAsync(int id) =>
    await _inner.GetUserAsync(id);  // same — pass-through allowed
```

## When suppression is legitimate

Almost never. If the method genuinely should propagate exceptions, its
return type should be `Task<T>` instead of `Task<TriedEx<T>>`.
