# NLF0020 — Async methods must declare a CancellationToken parameter

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

A method that is async — it carries the `async` keyword **or** its name ends
with the `Async` suffix — must declare a `System.Threading.CancellationToken`
parameter so the operation can be cancelled.

NLF0020 enforces only the **presence** of the token. Its **position** is owned
by CA1068 ("CancellationToken parameters must come last"), so the two rules
compose without overlapping: NLF0020 makes sure the token exists, CA1068 makes
sure it is last.

A single async method without a token is a dead end — it silently removes the
caller's ability to thread cancellation through the call graph. Together with
NLF0018 (the token must not be optional) and CA2016 (callers must forward an
in-scope token), NLF0020 keeps cancellation flowing end-to-end.

## Bad — async method with no token

```csharp
public sealed class Worker
{
    // ❌ NLF0020 — async keyword, no CancellationToken.
    public async Task RunAsync()
    {
        await DoWorkAsync(CancellationToken.None);
    }

    // ❌ NLF0020 — Async suffix, Task-returning, no CancellationToken.
    public Task<int> ComputeAsync() => Task.FromResult(42);
}

public interface IWorker
{
    // ❌ NLF0020 — the contract itself omits the token.
    Task RunAsync();
}
```

## Good — token declared (CA1068 keeps it last)

```csharp
public sealed class Worker
{
    public async Task RunAsync(CancellationToken cancellationToken)
    {
        await DoWorkAsync(cancellationToken);
    }

    public Task<int> ComputeAsync(CancellationToken cancellationToken)
        => Task.FromResult(42);
}

public interface IWorker
{
    Task RunAsync(CancellationToken cancellationToken);
}
```

## When the analyzer stays silent

NLF0020 does **not** fire when:

- The method already has a `CancellationToken` parameter (anywhere in the
  signature — position is CA1068's job).
- The method is an `override` — the base owns the signature; fix it there.
- The method implements an interface member (implicitly or explicitly) — the
  interface owns the signature; fix it on the interface.
- The method is an `async void` event handler shaped `(object, EventArgs)` —
  the delegate signature is fixed by the event.
- The method carries a test attribute (`[Fact]`, `[Theory]`, `[Test]`,
  `[TestCase]`, `[TestMethod]`, `[DataTestMethod]`) — the test framework
  invokes it; there is no caller to thread a token.
- The method is named by a **test data source attribute** in the same
  compilation (`[MemberData]`, `[TestCaseSource]`, `[ValueSource]`,
  `[DynamicData]`, `[MethodDataSource]`) — see below.
- The method is a static `Main` entry point.
- The containing type declares a **same-named sibling overload** that takes a
  `CancellationToken` — the token-free overload is a convenience entry point
  (the BCL `ExecuteNonQueryAsync()` / `ExecuteNonQueryAsync(CancellationToken)`
  pattern), and the sibling already lets callers thread a token.
- The method accepts a **delegate-typed parameter** (`Func<…>`, `Action`,
  `EventHandler`, a custom delegate, or the base `System.Delegate` /
  `System.MulticastDelegate`) — cancellation belongs to the caller-supplied
  delegate, which closes over its own token.

## Test data source members

A theory data provider is a framework callback, not an application API. The
test framework locates it by name from an attribute on the consuming test and
invokes it with only the arguments the attribute supplies — no cancellation
token is passed. Adding a `CancellationToken` parameter to satisfy NLF0020
would therefore change a working provider into one the framework cannot
invoke.

NLF0020 stays silent when a method is named by one of these attributes
**anywhere in the same compilation**:

| Framework | Attribute | Declaring type comes from |
|-----------|-----------|---------------------------|
| xUnit | `[MemberData]` | `MemberType = typeof(T)`, else the test class |
| NUnit | `[TestCaseSource]`, `[ValueSource]` | `typeof(T)` argument, else the test class |
| MSTest | `[DynamicData]` | `typeof(T)` argument, else the test class |
| TUnit | `[MethodDataSource]` | `typeof(T)` argument or `<T>`, else the test class |

```csharp
public sealed class ExampleTests
{
    // ✅ No NLF0020 — [MemberData] below names this member.
    public static async Task<IEnumerable<object[]>> GetCasesAsync()
    {
        await Task.Yield();
        return new[] { new object[] { 42 } };
    }

    // ❌ NLF0020 — same shape, but nothing references it as a data source.
    public static async Task<IEnumerable<object[]>> LoadFixturesAsync()
    {
        await Task.Yield();
        return [];
    }

    [Theory]
    [MemberData(nameof(GetCasesAsync))]
    public void ValueIsPositive(int value) => Assert.True(value > 0);
}
```

Matching resolves the member on the declaring type **and its base types**, so a
provider inherited from a shared test base class is also exempt. Only the first
positional string (or `nameof`) argument is treated as the member name — trailing
arguments that the framework forwards *to* the provider are not.

The reference must live in the same compilation. A provider in a shared testing
library, referenced by `[MemberData]` from a different assembly, is invisible to
the analyzer and needs a declaration-scoped suppression.

## When suppression is the correct choice

For the rare async method that genuinely cannot accept a token — for example a
result-orchestration wrapper whose callback owns its own cancellation, or a
framework-shaped delegate target the rule's exemptions do not cover — suppress
at the declaration with a reason:

```csharp
// Wraps a caller-supplied callback that owns its own cancellation; this method
// has no I/O of its own to cancel.
#pragma warning disable NLF0020
public static async Task<TriedEx<T>> GetAsync<T>(Func<Task<T>> work)
#pragma warning restore NLF0020
{
    /* ... */
}
```

Opt the whole project out via `dotnet_diagnostic.NLF0020.severity = none`.

## Related rules

- **CA1068** (Microsoft NetAnalyzers) — enforces that the token is the last
  parameter. NLF0020 (presence) + CA1068 (position) together require a
  trailing `CancellationToken` on every async method.
- **NLF0018** — the declared token must not be optional (`= default`).
- **CA2016** (Microsoft NetAnalyzers) — callers must forward an in-scope token
  to methods that accept one.
- **RCS1047** (Roslynator) — a method named `...Async` that is neither async
  nor task-returning should drop the suffix.
