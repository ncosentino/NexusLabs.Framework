### New Rules

Rule ID | Category | Severity | Notes
--------|----------|----------|-------
NLF0001 | Usage    | Warning  | Do not use Console.Write / Console.WriteLine / Debug.Write / Debug.WriteLine in library code. Route output through ILogger or similar.
NLF0002 | Usage    | Warning  | Do not access TriedEx/TriedNullEx Value without first checking Success is true.
NLF0003 | Usage    | Warning  | Do not access TriedEx/TriedNullEx Error without first checking Success is false.
NLF0004 | Usage    | Warning  | Redundant null check on TriedEx/TriedNullEx Error after Success has been established as false (Error is guaranteed non-null).
NLF0005 | Usage    | Warning  | When returning an exception from a TriedEx/TriedNullEx Success-false branch, preserve the original Error (return it, wrap as inner, or include in aggregate).
NLF0006 | Usage    | Warning  | Async method whose entire body is a single try-catch should use Try.Async / Try.GetAsync / Try.GetOrNullAsync.
NLF0007 | Usage    | Warning  | Method-scoped Try.Async variants should be invoked with an ILogger argument.
NLF0008 | Usage    | Warning  | Do not throw inside a Try.Async variant callback — return the exception instead.
NLF0009 | Usage    | Warning  | Async method returning Task&lt;TriedEx&lt;T&gt;&gt;/Task&lt;TriedNullEx&lt;T&gt;&gt; should wrap its body with Try.GetAsync / Try.GetOrNullAsync (direct pass-through is allowed).
NLF0010 | Usage    | Warning  | Multi-line raw string literal opening triple-quote must be on its own line, aligned with the closing triple-quote.
NLF0011 | Usage    | Warning  | TriedEx/TriedNullEx/Tried local whose type argument implements IDisposable/IAsyncDisposable should be declared with `using` (or otherwise consumed via return, argument pass, or explicit Dispose).
NLF0012 | Usage    | Warning  | Parameterless `[TransfersOwnership]` applied to a member whose type is not IDisposable/IAsyncDisposable is silently ignored by NLFSUP001. Add target names for Shape A, or move the attribute onto the disposable member for Shape B.
NLF0013 | Usage    | Warning  | Use a [StronglyTypedId]-decorated ID's own `Parse(string)` / `TryParse(string, out T)` static methods instead of constructing the ID from a value pre-parsed via the backing type (`new XxxId(Guid.Parse(s))` or `if (Guid.TryParse(s, out var v)) { new XxxId(v); }`).
NLF0014 | Usage    | Warning  | Call to `Type.Parse` / `Type.TryParse` should pass an explicit `IFormatProvider` when an overload accepting one exists. Implicit-culture parsing is a frequent source of locale-dependent bugs.
NLF0015 | Usage    | Warning  | A method whose name uses the `Try` prefix (e.g. `TryGetAsync`, `TryParse`) must return `TriedEx<T>`, `TriedNullEx<T>`, or `Exception?` (optionally wrapped in `Task<>`/`ValueTask<>`). The prefix is a contract — using it on a method that returns `bool`, `T?`, `void`, etc. silently breaks the convention every other Try method follows. Skips overrides, interface implementations, members of `NexusLabs.Framework.Try`, and underscore-delimited test method names.
NLF0016 | Usage    | Warning  | `HashSet<string>` constructors and the `Enumerable.ToHashSet(IEnumerable<string>)` extension must pass `StringComparer.OrdinalIgnoreCase`. A string-keyed set without an explicit case-insensitive comparer treats `"Foo"` and `"foo"` as different keys — almost never the intent for config keys, header names, file paths, or identifiers. Non-string `HashSet<T>` is unaffected.
NLF0017 | Usage    | Warning  | Classes implementing `Carter.ICarterModule` must be declared `public sealed class`. Carter discovers modules via reflection over PUBLIC types only — a non-public module compiles cleanly but its routes silently return 404 at runtime with no build error. The analyzer matches `Carter.ICarterModule` by namespace + type-name in the consumer's compilation; no Carter package reference required in the analyzer assembly.
NLF0018 | Usage    | Warning  | `CancellationToken` parameters must not carry a default value. Optional tokens let callers silently drop the token so downstream I/O ignores cancellation. Applies to every method, constructor, local function, and delegate signature — no scope, no kind filter, no built-in escape hatch. Pass `CancellationToken.None` explicitly when truly no token is available, or suppress per-method with `#pragma warning disable NLF0018` for intentional public-API ergonomic defaults or `[EnumeratorCancellation]` iterators.
NLF0019 | Performance | Warning | Allocating an empty collection (any constructed type — `List<T>`, `Dictionary<TKey,TValue>`, `HashSet<T>`, `SortedDictionary`, `ObservableCollection`, user-defined collections, …) only to expose it through a read-only collection interface (`IEnumerable<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, `IReadOnlyDictionary<TKey,TValue>`, `IReadOnlySet<T>`) wastes a per-call allocation the caller can never mutate. Return a shared empty instead: `[]` for the list family, `ReadOnlyDictionary<TKey,TValue>.Empty`, or `FrozenSet<T>.Empty`. Fires only on provably-empty creations widened to a read-only interface (so mutate-then-return is safe); the mutable interfaces (`IList`/`ICollection`/`ISet`/`IDictionary`) and zero-length arrays (CA1825) are excluded. Has a code fix.
NLF0020 | Usage    | Warning  | A method that is async (carries the `async` keyword OR whose name ends with the `Async` suffix) must declare a `System.Threading.CancellationToken` parameter so the operation can be cancelled. NLF0020 enforces token PRESENCE; CA1068 enforces its last-position. Skips overrides, interface implementations, `async void` event handlers (`(object, EventArgs)`), `[Fact]`/`[Theory]`/`[Test]`/`[TestMethod]` test methods, `Main`, same-named sibling overloads that take a `CancellationToken` (BCL convenience-overload pattern), and methods accepting a delegate-typed parameter (`Func`/`Action`/`EventHandler`/`Delegate`/`MulticastDelegate`). Suppress per-method with `#pragma warning disable NLF0020` for a genuinely uncancellable async method.
NLF0021 | Usage    | Warning  | Moq mocks must be created from a shared `MockRepository` (`_mocks.Create<T>()`), not via `new Mock<T>(...)` or `Mock.Of<T>(...)`. A shared repository gives every mock one strict behavior and lets `VerifyAll()` assert all setups. Matches `Moq.Mock<T>` and `Moq.Mock.Of` by namespace + name.
NLF0022 | Usage    | Warning  | Moq mocks must use `MockBehavior.Strict` so unconfigured calls fail fast. Fires on a `Moq.MockRepository` constructed with a non-Strict behavior and on a `repository.Create<T>(MockBehavior.Loose/Default, ...)` override. Direct `new Mock<T>(...)` is owned by NLF0021 and not double-flagged.
NLF0023 | Usage    | Warning  | `It.IsAny<T>()` where `T` is a value type (other than `CancellationToken`) or a record hides the value the code under test passed. Match the expected value directly or use `It.Is<T>(x => ...)`. `CancellationToken` is exempt; reference types and open generic type parameters are unaffected.
NLF0024 | Usage    | Warning  | `RentedSpan<T>` (namespace `NexusLabs.Framework.Buffers`) is a single-owner, move-only pooled-buffer `ref struct`. Any read of a handle that materializes a second value — assignment, variable initializer (incl. `using var b = handle;`), by-value argument, ternary/switch-expression branch, or returning a `using`-bound handle — creates a second owner of the same rented array, so disposing both copies double-returns it and corrupts the pool. Invoking a non-`readonly` member (e.g. `Dispose()`) through an `in`/`ref readonly` handle is flagged too (silent defensive copy). By-reference uses (member/element-access receiver, `ref`/`in`/`out` arg, assignment target, `using` resource, `nameof`, `is` pattern, discard), a fresh `RentSpan` acquisition, and a bare `return` move of a non-`using` local are not flagged. The reference-type `RentedMemory<T>` is not analyzed — copies share one owner, so returns stay correct by construction. Heap escapes (boxing, fields, capture, collections, crossing `await`) are already compile errors for the `ref struct`. Suppress with `#pragma warning disable NLF0024` for a deliberate ownership transfer.
NLF0025 | Usage    | Warning  | A call or construction that has an overload accepting `System.TimeProvider`, made where a clock is already reachable (enclosing method parameter, instance field/property on the type or a base type, or a constructor parameter including a primary constructor) but was not passed. Covers invocations (`Task.Delay`) and object creations (`new CancellationTokenSource(delay)`, `new PeriodicTimer(period)`) alike. An overload counts only when it takes strictly more parameters than the resolved target. Static members are excluded so the inherited `TimeProvider.System` is never offered as the available clock. Mutually exclusive with NLF0026. Suppress with `#pragma warning disable NLF0025` for a call that must intentionally use real time.
NLF0026 | Usage    | Info     | The NLF0025 companion for a call site where no `System.TimeProvider` is reachable. Ships at Info because the fix is an API change (accept a clock through the surrounding method or type) rather than a defect in the statement. Raise via `dotnet_diagnostic.NLF0026.severity = warning` in a codebase committed to injecting a clock everywhere.
NLF0027 | Usage    | Warning  | An interface that reimplements `System.TimeProvider`. Fires when every member is time related AND at least one is a clock member (`Now`/`UtcNow`/`GetNow`/`GetUtcNow`/`GetLocalNow`/`CurrentTime`/`GetTimestamp` returning `DateTime`/`DateTimeOffset`/`long`). Delay members (`Delay`/`DelayAsync`/`Sleep`/`SleepAsync`/`WaitAsync`/`CreateTimer` taking a `TimeSpan`) are counted as time related, so the common clock-plus-delay shape is reported rather than exempted. A broader interface that merely exposes a timestamp alongside unrelated members is not reported.
NLF0028 | Usage    | Warning  | An `override` of `CreateTimer` on a class deriving from `Microsoft.Extensions.Time.Testing.FakeTimeProvider` whose body never calls `base.CreateTimer`. Replacing the timer bypasses the virtual-time scheduler, so every delay in the system under test completes on its own schedule and tests pass without exercising the delay. Observe registrations by calling `base.CreateTimer(...)` and returning a wrapper that forwards `Change`/`Dispose`/`DisposeAsync` instead; an override that delegates is not reported.
