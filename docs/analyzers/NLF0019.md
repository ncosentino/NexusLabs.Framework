# NLF0019 — Return a shared empty collection instead of allocating one for a read-only result

**Severity:** Warning · **Category:** Performance · **Code-fix:** Yes

Allocating a fresh empty collection only to hand it back through a
**read-only** collection interface wastes a heap allocation on every
call: the caller can never mutate the value through that interface, so
a single cached empty instance is always preferable. It is also
genuinely immutable, rather than a mutable collection hidden behind a
read-only facade.

The rule fires when an **empty** collection — of *any* constructed type
— is **widened to a read-only collection interface**:

| Read-only target | Shared empty to use |
|------------------|---------------------|
| `IEnumerable<T>` / `IReadOnlyCollection<T>` / `IReadOnlyList<T>` | `[]` (lowers to the cached `Array.Empty<T>()`) |
| `IReadOnlyDictionary<TKey,TValue>` | `ReadOnlyDictionary<TKey,TValue>.Empty` |
| `IReadOnlySet<T>` | `FrozenSet<T>.Empty` |

It triggers on `return`, expression-bodied members, field/property
initializers, and arguments — anywhere an empty collection is
implicitly converted to one of those interfaces. The **concrete
collection type is irrelevant**: the read-only interface is the entire
signal that the value is never modified, so `List<T>`, `Dictionary<K,V>`,
`HashSet<T>`, `SortedDictionary<K,V>`, `ObservableCollection<T>`, and
user-defined collection types all qualify.

## Bad — allocating a throwaway empty collection

```csharp
public IReadOnlyList<int> GetItems()
{
    if (_source is null)
    {
        return new List<int>();                 // wasteful empty allocation
    }
    // ...
}

public IReadOnlyDictionary<string, int> GetCounts() => new Dictionary<string, int>();

public IReadOnlySet<string> GetTags() => new HashSet<string>();

private static readonly IReadOnlyList<int> Seed = new List<int>();   // initializer, same waste

void Process(IReadOnlyList<int> items);
Process(new List<int>());                       // argument, same waste

// The concrete type does not matter — these are flagged too:
public IReadOnlyDictionary<string, int> Sorted() => new SortedDictionary<string, int>();
public IReadOnlyList<int> Observable() => new ObservableCollection<int>();
```

## Good — shared empty instance

```csharp
public IReadOnlyList<int> GetItems()
{
    if (_source is null)
    {
        return [];                              // cached Array.Empty<int>()
    }
    // ...
}

public IReadOnlyDictionary<string, int> GetCounts() => ReadOnlyDictionary<string, int>.Empty;

public IReadOnlySet<string> GetTags() => FrozenSet<string>.Empty;

private static readonly IReadOnlyList<int> Seed = [];

Process([]);
```

`[]` and `Array.Empty<T>()` compile to the exact same cached, zero-length
array singleton — `[]` is just the terser spelling. For read-only
dictionaries and sets there is no collection-expression form (the
compiler rejects `[]` for `IReadOnlyDictionary<K,V>` / `IReadOnlySet<T>`
with `CS9174`), so the named `.Empty` singletons are the only
allocation-free option.

## When the analyzer stays silent

- **The creation is not empty** — `new List<int> { 1, 2 }`,
  `new Dictionary<string, int>(source)`, `new HashSet<int>(comparer)`,
  or any constructor with arguments (including a capacity such as
  `new List<int>(16)`).
- **No widening to a read-only interface** — the declared type is the
  concrete collection (`List<int> x = new()`) or a *mutable* interface
  (`IList<T>`, `ICollection<T>`, `ISet<T>`, `IDictionary<TKey,TValue>`).
  Mutable interfaces are excluded on purpose: their callers may `Add`,
  and a fixed-size shared empty would throw.
- **Mutate-then-return** — the creation is assigned to a local and
  populated before being returned. Because the creation's *converted*
  type is the mutable collection (not the interface), it is left alone:

  ```csharp
  IReadOnlyList<int> Build()
  {
      var items = new List<int>();   // converted type is List<int> — not flagged
      items.Add(1);
      return items;
  }
  ```

- **Already optimal** — `return [];` is never flagged; for a read-only
  list target it is already the cached singleton.
- **The `.Empty` member is unavailable** — on a target framework below
  .NET 8 (where `ReadOnlyDictionary<K,V>.Empty` / `FrozenSet<T>.Empty`
  do not exist) the dictionary and set branches stay silent rather than
  suggest an API that will not compile.

## Suppressing

For a deliberate fresh-empty allocation, suppress per-site with an
inline comment naming the reason:

```csharp
#pragma warning disable NLF0019
// Caller is documented to receive a private, growable buffer despite
// the read-only return type.
return new List<int>();
#pragma warning restore NLF0019
```

Per-project, opt out via
`dotnet_diagnostic.NLF0019.severity = none` in `.editorconfig`.

## Related rules

- **CA1825** (*Avoid zero-length array allocations*) covers the array
  case — `new T[0]` → `Array.Empty<T>()`. NLF0019 deliberately does not
  touch arrays so the two rules do not overlap; together they cover the
  full "don't allocate a forever-empty collection" space.
- **NLF0016** (`HashSet<string>` comparer) is the other collection-
  construction rule in this package; it is orthogonal (it is about
  equality semantics, not allocation).
