# NLF0007 — Pass ILogger to method-scoped Try.Async variant

**Severity:** Warning · **Category:** Usage · **Code-fix:** No

When `Try.Async` / `Try.GetAsync` / `Try.GetOrNullAsync` wraps the entire
body of a method, the caller benefits from automatic exception logging.
Pass an `ILogger` as the first argument so the Try helper emits a
structured error on catch. The logger-less overloads are intended for
nested or transient calls where the enclosing context already owns the
logging.

## Bad

```csharp
public Task<TriedEx<User>> GetUserAsync(int id) =>
    Try.GetAsync(async () => await _repo.GetByIdAsync(id));
    // entire method body is Try; logger overload should be used
```

## Good

```csharp
public Task<TriedEx<User>> GetUserAsync(int id) =>
    Try.GetAsync(_logger, async () => await _repo.GetByIdAsync(id));
```

## When suppression is legitimate

Inside an expression that is itself nested in a larger logged operation:

```csharp
public async Task<int> CountAsync(IEnumerable<int> ids)
{
    int total = 0;
    foreach (var id in ids)
    {
        var result = await Try.GetAsync(async () => await GetSizeAsync(id));
        if (result.Success) total += result.Value;
    }
    return total;
}
```

The outer method owns the logging; per-iteration Try calls don't need
their own logger.
